# Task: v2.1 hardening plan — borrowings from the alternative edge-framework design review

- [x] Execute the hardening in phases H1–H7 below, on `refactor/20261003-audits`, committing sequentially.

  **Context:** A parallel/alternative design ("Workflow Engine Framework Specification v2.0",
  edge/IoT, message-bus DAG, snapshot-checkpoint persistence, interface-per-concern) was
  reviewed against the refactored engine (tip `45114fc`, v2.0.0). Verdict: borrow its
  *concerns checklist*, reject its *form* (it re-plants the interface forest the 20261003
  refactor demolished, and duplicates state ×4 in its execution object). Five concerns were
  selected as borrowable — each maps onto the log-as-truth architecture as a concrete type,
  not a new interface pyramid:

  1. **Log compaction** (spec §5.2 checkpoints) — but as *derived caches of the log*, never a
     second source of truth. The final gate honestly documented seq-fold rebuild at
     ~1.9µs/delta, linear in history length; paused-run rebuilds after a restart pay the full
     walk. A pause-time fold snapshot makes that rebuild O(1) in history length.
  2. **Definition version pinning** (spec §5.1 `DefinitionVersion`) — the restart rebuild
     (S.3) currently replays paused runs against *whatever definition is now registered*.
     A changed pipeline between restarts silently shifts replay semantics: the §D divergence
     bug class, reborn. Pin a structural fingerprint; detect drift; make it loud.
  3. **Retention + storage contract** (spec §5.2 storage mgmt) — the janitor's horizons are
     internal constants; the durable log grows unboundedly; hosts have no usage introspection.
  4. **Runtime health snapshot** (spec §7 health/`GetBufferStatus`) — hermes exposes no
     `Health()` at all; embedding hosts have no cheap introspection for dashboards.
  5. **Resource budgets + typed validation errors** (spec §7.1, §3.2) — selective: a spawn-time
     state budget, a global run gate, buffered-event TTL, and error codes hosts can match on.

  **What was rejected, and why (recorded so it stays rejected):** interface-per-concern form
  (~14 single-implementation interfaces — R.3 deleted 11 of exactly these); snapshot-as-truth
  recovery (checkpoints embedded in the execution object = state duplication ×4 — the §E
  class); shared mutable `GetState`/`SetState` node maps (the lock-around-user-code deadlock
  class, C1/C4); `MessageHistory` embedded in the execution (unbounded duplicate of the log);
  a `MetricsCollector` interface (a third observability channel — metrics belong to the host);
  per-message bus priorities (in-process dispatch is µs-scale; priorities reintroduce the
  ordering hazards C5 just removed). The durable-outbox checklist (spec §4.2) stays rejected
  for the in-process engine but is archived in docs as the requirements list IF a distributed
  mode is ever attempted — it is what the deleted "durable bus" of D.1 should have specified.

## Non-negotiables

1. **Every commit:** `go vet ./...` + `go test -race ./...` green (25+ pkgs), `gofmt -s` clean.
   Run `gofmt -w` on every file the Write/Edit tools touch — the toolchain emits tabs; the
   editing sessions drift to spaces (1ffb916 precedent).
2. **No deletions, no wire changes.** v2.1 is additive only: new optional `Options` fields,
   new optional capability interfaces (the established data-driven pattern: `RunEnumerator`),
   new additive JSON fields. `PipelineCheckpoint` (SPEC §8 wire shape) is NOT touched — the
   fingerprint rides on `actionlog.Entry.DefHash` (additive field; old readers ignore it; old
   logs read as empty = check skipped). Version: **v2.1.0** (not v3 — nothing breaks).
3. **Snapshot is a cache, log is the truth.** The fold snapshot must be *provable* equal to
   the walk's result, and every fast path must degrade to the full walk on ANY doubt (missing,
   stale, corrupt, drifted, racy). The gate is fail-closed toward the walk, never toward the
   checkpoint seed (that degraded path stays as loud as R.4 made it).
4. **Layering discipline (R.6):** no new `internal/` imports from `pkg/`; the layering test's
   whitelist gets entries ONLY with a written reason (unused whitelist entries fail).
   `pipeline.Fingerprint` lives in `pkg/pipeline` (types it hashes); snapshot capability in
   `pkg/actionlog` (it persists next to entries); decisions in `internal/runtime/recovery.go`
   (the ONE recovery decision point, R.4).
5. **Honest bench evidence:** H2 lands with benchstat before/after on `Rebuild_*` — including
   the non-paused case (walk path unchanged) and the parity story. No regression shipped
   unexplained; if a change regresses a P4 win, it is reverted or re-scoped, not rationalized.
6. **No new public interface has exactly one production implementation.** The two new
   capability interfaces (snapshot store, usage/prune) are optional capabilities with two
   implementations each (memory + anansi/sqlite), asserted by type — the `RunEnumerator`
   pattern, not the R.3 pattern.

## Phase H1 — definition fingerprint + drift detection (2 commits)

**H1.1 `pipeline.Fingerprint`** (`pkg/pipeline/fingerprint.go` + tests)
- Structural, deterministic fingerprint (FNV-1a 128, hex) over the declarative surface the
  replay walk consumes: `PipelineDefinition.ID`; stages in SLICE order (order matters —
  the walk is sequential): ID, Timeout, Config canonical JSON, Steps sorted by ID:
  {ID, Timeout, Retries, Effect}, nested `Pipelines` recursively in slice order.
- EXCLUDED (documented in the file doc-comment): Labels (cosmetic), and all closure fields —
  `Action`, `Router`, `PipelinesRouter`, `DynamicPipelines`. Their behavior is Go code:
  structural hashing cannot see code changes. For compiled workflows node behavior derives
  from Config + the frozen catalog; for hand-built workflows a pure-code change with identical
  structure is UNDETECTED by design — state this limitation in RECOVERY.md, do not oversell.
- Canonical map JSON via sorted keys; stable across processes (no Go map iteration order).
- Tests: stability (same def twice = same hash; label-only change = same hash), sensitivity
  (stage reorder, step add/remove/reorder-by-key, config value change, effect-class change,
  nested subpipeline change all DETECTED), determinism across instances built separately.

**H1.2 drift stamping + detection + policy** (`internal/runtime`, `pkg/actionlog`, `pkg/pipeline`, `pkg/timeline`, tests)
- `actionlog.Entry` gains `DefHash string json:"defHash,omitempty"`.
- Workflow-level fingerprint: `workflowFingerprint(wf)` = sorted (triggerID, Fingerprint(def))
  over `wf.Pipelines` — a child-def edit drifts the whole workflow (the walk consumes children).
- Threading: `FactoryOptions.WorkflowHash` → `RunContextImpl.wfHash` (children inherit the
  parent's value at child-context construction) → `appendLog` stamps `DefHash` on
  `KindPipelineStarted` and `KindCheckpoint` entries when non-empty. Spawn + resume factory
  sites set it from `record`.
- Detection sites (recovery.go stays the single decision point):
  - `Resume` (same-process): `pausedRun.defHash` captured at both pause-bookkeeping sites
    (dispatch.go:207, pauseresume.go re-pause) vs `workflowFingerprint(current record)` —
    catches Deregister+Register of an edited workflow while runs are paused.
  - `rearmPausedRun` (S.3 restart): the re-arming pause's checkpoint entry `DefHash` vs the
    fingerprint of the workflow being registered.
  - `RunTimelineMeta` gains `DefHash`, `DefinitionDrift bool` (additive wire fields).
- `Options.DefinitionPolicy string`: `""`/`"warn"` (default) → loud Warn + tag meta.Drifted;
  `"require-same"` → Resume/re-arm returns the typed error
  `core.ErrCodeDefinitionDrift = "DEFINITION_DRIFT"` (new additive code) — a wrong-state
  resume is worse than a refused one, and hosts opt into refusal. Empty hash on legacy logs →
  check skipped (backward compat), never blocks.
- Tests: drift tagged under warn; require-same refuses with the typed code; legacy (hashless)
  logs pass; restart re-arm with edited workflow warns/refuses per policy; hashless checkpoint
  entries don't false-positive.

## Phase H2 — pause-time fold snapshots (2 commits)

**H2.1 snapshot store capability** (`pkg/actionlog` + tests)
- `FoldSnapshot{RunID string; RerunIndex int; Seq uint64; DefHash string; State json.RawMessage}`.
- Optional capability (RunEnumerator pattern): `FoldSnapshotStore { SaveFoldSnapshot(ctx, FoldSnapshot) error; LoadFoldSnapshot(ctx, runID string, rerunIndex int) (*FoldSnapshot, error) }`.
  Key: (runID, rerunIndex) — one snapshot per attempt, latest pause wins (INSERT OR REPLACE).
- `MemoryActionLog` implementation (map). `AnansiStore` implementation: new sqlite table
  `hermes_fold_snapshots(run_id TEXT, rerun_index INTEGER, seq INTEGER, def_hash TEXT,
  state BLOB, PRIMARY KEY(run_id, rerun_index))`, `CREATE TABLE IF NOT EXISTS` at open
  (migration-safe; `durable_log_test.go` harness verifies old-DB open).
- NOT an `Entry`: snapshots must never appear in `All()`/`Count()`/timeline — they are a
  side cache, invisible to the fold and the wire.

**H2.2 fast-path rebuild + parity + bench** (`internal/runtime/recovery.go`, tests, bench)
- Write side: `writeFoldSnapshot(runID, pipelineID, st, wfHash)` called at BOTH pause
  bookkeeping sites after the paused-registry write, BEFORE buffered delivery (C5 ordering:
  a chained re-pause's own bookkeeping then overwrites with the newer snapshot). Guarded:
  re-read latest attempt, last entry must be `KindCheckpoint`, parse its checkpoint,
  capture `st.ExportJSON()` (store read lock; marshal outside), `rt.mu` identity check that
  `rt.paused[runID]` is still THIS pause (ResumeAt equality) — races degrade to a stale
  snapshot that the read-side gate rejects (fail-closed). Best-effort: save errors are logged
  Warn, never fail the pause. Respects `Options.DisableFoldSnapshots`.
- Read side (`rebuildCapability`, the ONE decision point): when the log implements
  `FoldSnapshotStore` and `!rt.disableFoldSnapshots`: load snapshot for the latest attempt;
  gate = snapshot exists ∧ `snap.RerunIndex == latest` ∧ last entry of the attempt is
  `KindCheckpoint` at `Seq == snap.Seq` with a parseable `ResumeAt.Stage != ""` ∧
  `snap.DefHash == workflowFingerprint` (H1 composes here) ∧ parse of `snap.State` succeeds.
  ALL of it or NOTHING: any miss → the existing `Replayer.Rebuild` walk, byte-identical to
  today. Fast path returns (seeded MemoryStore, ckpt.ResumeAt) — the SAME contract shape
  `factory.Resume` already consumes; `copyStoreState` overlays runtime-seeded fields
  (checkpoint, payload, `__resume_reason__`) exactly as on the walk path.
- Correctness frame: for a currently-paused run, last entry = its KindCheckpoint, and the
  walk of entries 1..ckptSeq reproduces the store AS IT WAS AT PAUSE (the fold's own
  contract — golden vectors pin walk==live). Therefore snapshot(state@pause) == walk result
  when the gate holds. Parity is ASSERTED, not assumed:
  - `TestFoldSnapshotParity` matrix: simple pause, pause→resume→re-pause (chained C5),
    subpipeline pause (child ResumeAt), payload folded at resume, cron pause. Each: run to
    pause with snapshots ON, capture fast-path rebuild (store export + address) vs
    snapshots-OFF walk rebuild — deep-equal state, equal address.
  - `TestFoldSnapshotGate`: corrupt state JSON / stale seq / def-hash mismatch / missing
    snapshot / checkpoint-not-last → walk used, result identical (fail-closed proof).
- Bench (benchstat, P0-baseline discipline): `Rebuild_1000Entries_1Attempt` and
  `Rebuild_100Entries_10Attempts` with snapshots ON (paused-run shape) vs OFF (walk
  unchanged); the walk numbers must match the final-gate numbers within noise.
- `Options.DisableFoldSnapshots bool` doubles as the A/B test switch and the host escape hatch.

## Phase H3 — retention + storage contract (1 commit)

- `Options.StoreGrace time.Duration` (0 = keep the 10-minute `defaultStoreGrace`): tier-1
  terminal store-store eviction horizon becomes configurable (was a const; the audit-history
  tier stays `RunHistoryTTL` — no semantic change, one knob surfaced).
- `Options.MaxLogAge time.Duration` (0 = off): when the log implements the new optional
  `LogPruner { PruneRuns(ctx context.Context, olderThan time.Time) (int, error) }`, the
  janitor tick prunes WHOLE runs whose latest attempt ends in a TERMINAL kind older than the
  horizon. Paused/in-flight runs are never pruned (the SQL keys on the last entry's kind +
  timestamp per run). `AnansiStore` implements it (+ fold-snapshots rows for pruned runs);
  `MemoryActionLog` does NOT (nothing durable to prune — document why).
- Optional capability `UsageReporter { StorageUsage(ctx) (LogUsage, error) }` with
  `LogUsage{Runs, Entries, Bytes int64}` — `AnansiStore` (SQL aggregate over the entries
  table + snapshots), `MemoryActionLog` (len-based). Runtime exposes
  `StorageUsage(ctx) (LogUsage, error)` (typed error when the backend lacks the capability).
- Tests: prune keeps paused runs, keeps fresh terminal runs, removes old terminal ones and
  their snapshots; usage numbers sane after appends/prune; janitor wiring with MaxLogAge.

## Phase H5 — budgets and gates (1 commit)

- `Options.MaxStateBytes int64` (0 = off): HARD cap at the spawn boundary — initial state
  (trigger payload + seeds) exceeding the budget fails the run start with a typed
  `core.ErrCodeValidation` error naming the size. At pause bookkeeping: a WARN with the
  serialized size (the durability boundary where oversized states would be persisted).
  Documented honestly: budgets are enforced at durability boundaries, NOT per mutation —
  a single mid-run update can exceed the budget between boundaries; per-update measurement
  would reintroduce the P4.2 hot-path cost (delta-on-consumer).
- `Options.MaxActiveRuns int` (0 = off): global segment-scoped gate — acquire before
  `runCtx.Run()` on the spawn AND resume paths, release when the segment returns (paused
  runs release their slot; the gate bounds EXECUTING segments, which is what consumes CPU).
  Overflow: run start returns typed `core.ErrCodeConflict` (drop semantics match the
  per-workflow gate).
- `Options.EventTTL time.Duration` (0 = off): `WatchService` buffered events stamp
  `ReceivedAt`; on delivery (OnRunPaused drain + park-credit paths) expired events are
  dropped with a Debug log. Test: buffer an event, advance past TTL, resume delivers nil.
- Tests: budget reject at spawn; gate bounds concurrency under a burst (atomic counter
  probe); TTL expiry; all three off = zero behavior change (existing suites unchanged).

## Traps (learned the hard way on the v2 plan)

1. **Fail-closed direction**: every snapshot-path doubt must fall to the WALK, never to the
   checkpoint seed — the seed is the degraded path R.4 made loud; the snapshot must never
   silently introduce a THIRD recovery semantics.
2. **Chained re-pause (C5)**: snapshot writes sit BEFORE buffered delivery in both pause
   paths; the read gate's seq check makes any residual race harmless. Do not add locks that
   reorder against the pinned synchronous-resume contract.
3. **State at pause vs state at bookkeeping**: between the checkpoint append and the runtime's
   pause bookkeeping nothing may mutate the run store — verified per-site; if a site violates
   it, snapshot there is skipped (walk covers it), not forced.
4. **Map iteration order**: fingerprint + State JSON canonicalization sort keys everywhere;
   golden vectors + cross-instance determinism tests pin it.
5. **gofmt drift**: Write/Edit output → `gofmt -w` every touched file, every commit
   (1ffb916/d8e20b9 precedent). Bracket-sensitive strings in tests: build with chr(91)-style
   construction, verify with `od -c` (P4.6 lesson).
6. **Wire compat**: `PipelineCheckpoint` untouched; `Entry.DefHash`, `RunTimelineMeta.*`,
   `RuntimeHealth` are additive JSON. Old logs (no hashes) must flow through every new gate
   as "check skipped" — assert in tests, not just in comments.
